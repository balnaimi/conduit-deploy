Quick Start

Domain Setup

⚠️ IMPORTANT: Your Matrix server name is permanent. Once you create accounts and join rooms, you cannot change it. Choose carefully!

Two modes to choose from

Mode 1: Clean Usernames (with delegation)
Your Matrix ID: @alice:example.com (looks professional)
✅ Pros:
  • Clean, short usernames (@user:example.com)
  • Looks like your main domain (no "matrix." or "chat." prefix)
  • More professional for public servers
⚠️ Cons:
  • Requires delegation file on your main domain
  • Slightly more complex setup
  • Your main domain must serve /.well-known/matrix/server
Mode 2: Subdomain Only (simpler)
Your Matrix ID: @alice:matrix.example.com
✅ Pros:
  • Simpler setup — just one DNS record
  • No delegation file needed
  • Perfect for personal/private servers
⚠️ Cons:
  • Longer usernames (@user:matrix.example.com)
  • Less "clean" looking

Comparison Table

Feature Mode 1 (Delegation) Mode 2 (Subdomain)
Matrix ID @user:example.com @user:matrix.example.com
DNS Records 2 (A + SRV) 1 (A only)
Delegation File Required on main domain Not needed
Setup Complexity Medium Easy
Best For Public servers, businesses Personal/private servers

DNS Setup — Mode 1 (Delegation)

You want usernames like @alice:example.com but the server runs on matrix.example.com.

Step 1: DNS Records
Type Name Value TTL
A matrix.example.com Your server IP 3600
SRV _matrix._tcp.example.com 10 0 8448 matrix.example.com. 3600
Step 2: Delegation File
Your main domain (example.com) must serve this file at /.well-known/matrix/server:
{
  "m.server": "matrix.example.com:443"
}
How you create this file depends on your web server (Nginx, Apache, Caddy, etc.). The installer can guide you through this.

DNS Setup — Mode 2 (Subdomain Only)

You're okay with usernames like @alice:matrix.example.com. Simpler setup!

DNS Record
Type Name Value TTL
A matrix.example.com Your server IP 3600
That's it! No SRV record, no delegation file. Just point the subdomain to your server.
⚠️ Cannot change later!
Once you create accounts and join Matrix rooms, your server name is permanent. You cannot migrate from example.com to matrix.example.com (or vice versa) without losing all your data and re-creating accounts.

After Install

1. Download a Matrix Client

Your server is ready! Now you need an app to connect to it. Here are the most popular clients:

Client Platforms Link
Element Web, Desktop, iOS, Android element.io/download
SchildiChat Desktop, iOS, Android schildi.chat
FluffyChat iOS, Android, Linux fluffychat.im

2. Sign In

Connect to your homeserver
  1. Open your Matrix client (e.g., Element)
  2. Click "Sign In"
  3. Click "Edit" next to the homeserver URL
  4. Enter your server name:
    • Mode 1: example.com (no https://)
    • Mode 2: matrix.example.com
  5. Sign in with your username and password (from installer output)
Your first account was created automatically by the installer. Check the output for your username and password!

3. Create More Accounts

Register new users
By default, registration is disabled for security. You can enable it temporarily or create accounts manually.

Method 1: Enable registration (temporary)

sudo ./install.sh
# Choose option 2 (Change configuration)
# Set "allow_registration = true"
# Don't forget to disable it again after creating accounts!

Method 2: Create account via command line

docker exec -it conduit /bin/sh
conduit database create-user @newuser:example.com newpassword
exit

4. Security Tips

  • 🔒 Keep registration disabled unless you're actively creating accounts
  • 🔑 Use strong passwords for all accounts
  • ✅ Enable cross-signing in your client for device verification
  • 💾 Backup your encryption keys (Settings → Security → Backup)
  • 🛡️ Review your firewall rules — only ports 80, 443, 8448, 3478, 5349 should be open
  • 🔄 Keep Conduit updated regularly (run the installer and choose "Update")

Frequently Asked Questions

What is Matrix?
Matrix is an open protocol for secure, decentralized communication. Think of it like email — anyone can run a Matrix server, and all servers can talk to each other (federation). Unlike WhatsApp or Telegram, you control your data and can run your own server.
Why run your own Matrix server?
  • 🔐 Privacy: Your messages stay on your server, not someone else's
  • 🛡️ Control: You decide who can register, what features are enabled
  • 🌐 Federation: Still talk to users on other Matrix servers (matrix.org, etc.)
  • 📚 Learning: Great way to understand self-hosting and encrypted communication
  • 💰 Cost: Free if you already have a VPS or home server
How is this different from WhatsApp/Telegram/Signal?

Is it secure?
Yes! Matrix uses the Olm/Megolm encryption protocols (same family as Signal's Double Ratchet). All messages are end-to-end encrypted by default. Your server cannot read message contents — only metadata like who talked to whom and when.
Important: Security depends on keeping your server updated and following best practices (strong passwords, firewall rules, regular backups).
How many users can it handle?
Conduit is lightweight — it can handle dozens to hundreds of users on modest hardware. For reference:
  • 1-10 users: 1GB RAM, any CPU (Raspberry Pi works!)
  • 10-100 users: 2-4GB RAM, 2+ CPU cores
  • 100-500 users: 4-8GB RAM, 4+ CPU cores
This deployment uses ~50MB of RAM for Conduit itself, plus Caddy (~30MB) and Coturn (~20MB) = ~100MB total for a small server.
Can I change the server name later?
❌ NO! Your Matrix server name is permanent.
Once you create accounts and join rooms, your server name is locked in. If you change it, all your accounts become invalid, and you lose access to all rooms. There is no migration tool — you'd have to start from scratch.
⚠️ Think carefully before choosing!
Pick a domain you'll keep long-term. If you're unsure, use Mode 2 (subdomain) — it's simpler and you can always add delegation later if you want cleaner usernames.
How do I backup my server?
docker compose down
sudo tar czf conduit-backup-$(date +%F).tar.gz /opt/conduit
docker compose up -d
This backs up your database, configuration, and media files. Store the backup somewhere safe (off-site, encrypted).
How do I update Conduit?
sudo ./install.sh
# Choose option 3 (Update to latest version)
The installer pulls the latest Conduit image and restarts the services. Your data is preserved.

Architecture

How it all works

┌─────────────────────────────────────────────────────────────┐ │ Internet │ │ ↓ │ │ Ports 80, 443, 8448, 3478, 5349 │ └────────────────────┬────────────────────────────────────────┘ │ ┌──────────▼──────────┐ │ Caddy (Reverse │ ← Auto HTTPS, TLS certificates │ Proxy) │ ← Routes traffic to Conduit └──────────┬──────────┘ │ ┌──────────▼──────────┐ │ Conduit (Matrix │ ← Matrix homeserver (no ports exposed!) │ Homeserver) │ ← Runs isolated in Docker network └─────────────────────┘ │ ┌──────────▼──────────┐ │ Coturn (TURN/ │ ← Handles voice/video NAT traversal │ STUN server) │ ← Ports 3478 (UDP), 5349 (TCP/UDP) └─────────────────────┘
Security note: Conduit does not expose any ports directly. All external traffic goes through Caddy, which handles TLS termination and reverse proxying. Conduit only listens on the internal Docker network.

Port Table

Port Protocol Service Purpose
80 TCP Caddy HTTP (redirects to HTTPS)
443 TCP Caddy HTTPS (Matrix client-server API)
8448 TCP Caddy Matrix federation (server-to-server)
3478 UDP Coturn STUN (voice/video NAT discovery)
5349 TCP/UDP Coturn TURNS (encrypted voice/video relay)
