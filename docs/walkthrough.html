Walkthrough: Subdomain Mode

A complete real-world example — from a blank server to sending your first message.
This guide uses subdomain mode with matrix.example.com.

📋 What We'll Do

  1. Prerequisites — What you need before starting
  2. DNS Setup — Point your domain to your server
  3. Run the Installer — Launch the script and configure
  4. Health Check — Verify everything works
  5. Create Accounts — Add users to your server
  6. Sign In & Chat — Connect with a Matrix client

1. Prerequisites

Before you start, make sure you have:

WhatDetails
A VPS / serverDebian 13 or Ubuntu 22.04+ with at least 512MB RAM and 10GB disk. Any provider works (DigitalOcean, Hetzner, Linode, etc.)
Root accessEither logged in as root, or a user with sudo
A domain nameAny domain you own (e.g., example.com). You'll create a subdomain like matrix.example.com
DNS accessAbility to add DNS records (A and AAAA) at your domain registrar or DNS provider
💡 Tip: Not sure which mode to choose? Check the Domain Setup page first. This walkthrough uses Subdomain Mode (Mode 2), which gives you usernames like @user:matrix.example.com.

2. DNS Setup

Go to your DNS provider and add these records pointing to your server's IP address:

TypeNameValueTTL
AmatrixYour server's IPv4 (e.g. 188.166.248.91)3600
AAAAmatrixYour server's IPv6 (if available)3600
⏱️ Wait for DNS: After adding the records, wait a few minutes for them to propagate. You can verify with:
dig matrix.example.com +short
This should return your server's IP address.

3. Run the Installer

SSH into your server and run the script:

# SSH into your server
ssh root@your-server-ip

# Download and run the installer
curl -sL https://raw.githubusercontent.com/balnaimi/conduit-deploy/main/conduit-deploy.sh | bash

The script will show you a menu. Choose option 2 (Install).

3a. Choose Your Mode

The script asks how you want usernames to look:

* How do you want your usernames to look?

  1) Clean username — @user:example.com (server at matrix.example.com)
  2) Subdomain only — @user:matrix.example.com (simpler, no delegation)

Choose [1/2]:

For this walkthrough, choose 2 (Subdomain mode).

3b. Enter Your Domain

The script asks for your domain and subdomain:

Your domain name: example.com
Subdomain for the server [matrix]: matrix
VPS public IP [188.166.248.91]: ↵ (press Enter to accept)
💡 Note: Enter just the root domain (e.g. example.com), not the full address. The script combines it with the subdomain automatically.

3c. Media Settings

The script asks about file upload limits and storage. The defaults are good for most setups — just press Enter to accept each one:

SettingDefaultWhat It Means
Max upload size100 MBLargest file a user can send
Max media storage10 GBTotal space for all files (auto-cleans oldest)
Cached files idle expiry30 daysDelete cached files from other servers if nobody opened them in 30 days
Cached files max age90 daysDelete cached files older than 90 days regardless
User files idle expiry365 daysDelete your users' uploaded files if nobody opened them in a year
Thumbnail storage1 GBSpace for auto-generated image previews

3d. Confirm & Install

The script shows a summary of your settings:

Summary:
  Server name: matrix.example.com
  Usernames:   @user:matrix.example.com
  Matrix URL:  https://matrix.example.com
  VPS IP:      188.166.248.91
  .well-known: Not needed (subdomain mode)

Start installation? [Y/n]

Press Y to start. The installer will:

  1. Check all dependencies and install missing ones (Docker, UFW, Fail2ban, etc.)
  2. Verify ports 80, 443, and 8448 are available
  3. Verify DNS resolves to your IP
  4. Optionally set your timezone
  5. Generate configuration files and secrets
  6. Pull Docker images and start services
  7. Obtain a Let's Encrypt TLS certificate automatically
  8. Set up TURN server (for voice/video calls)
⏱️ How long? First install takes about 5–10 minutes depending on your server speed and internet connection. Most of the time is spent pulling Docker images.

4. Health Check

After install, run a health check to make sure everything is working. From the main menu, choose 3 (Health Check).

The health check verifies:

🟢 FederationPort 8448 accessible (so other servers can reach you)

🟢 FirewallUFW active with correct rules
🟢 Fail2banBrute-force protection running
🟢 SSHPassword authentication disabled

5. Create Accounts

Your server is running but has no users yet. Let's create some accounts.

Option A: Using the Script (Recommended)

From the main menu, choose 4 (Registration), then 3 (Create account via API).

# The script prompts you:
Username (without @, lowercase letters/numbers/dots/hyphens): alice
Password (min 8 characters): MySecurePass123!

The script handles everything automatically:

  1. Temporarily opens registration (with token protection)
  2. Creates the account via the Matrix API
  3. Closes registration again immediately
# Output:
ℹ Temporarily opening registration...
  Registration briefly open (token still required). Will close after account creation.
ℹ Creating account @alice:matrix.example.com...
✅ Account created: @alice:matrix.example.com
ℹ Registration closed again
🔒 Security: Registration stays closed between account creations. Even while it's briefly open, a registration token is required — random signups cannot get in.

Create as many accounts as you need: After each one, you're returned to the Registration menu. Choose 3 again for the next account.

Option B: Open Registration (Self-Service)

If you want users to sign up themselves, you can open registration:

  1. From the Registration menu, choose 1 (Open registration)
  2. Share your server address and registration token with your users
  3. When done, choose 2 (Close registration) to lock it down

To see your registration token:

# From the Registration menu, choose 4 (Show registration token)
Registration token: abc123xyz...

# Users enter this token during sign-up in their Matrix client.
⚠️ Don't forget! Always close registration when you're done. An open server can be found by scanners and filled with spam accounts. The script will warn you on startup if registration is left open.

6. Sign In & Chat

Now sign in with a Matrix client and start chatting!

6a. Download a Client

ClientPlatformsLink

6b. Sign In

  1. Open the app and tap "Sign In"
  2. Look for "Homeserver" or "Edit server" and change it to:
    matrix.example.com
  3. Enter your username (e.g. alice) and password
  4. You're in! 🎉

6c. Send a Message

To test, create a room or message another user on your server:

  1. Click "+" → "New direct message"
  2. Type the other user's full Matrix ID: @bob:matrix.example.com
  3. Send a message — it's end-to-end encrypted by default! 🔐
🌐 Federation: Your server can also talk to any other Matrix server. Try messaging someone on matrix.org — it just works!

🎉 You're Done!

Your Matrix server is running, secured, and ready to use. Here's what you might want to do next:

  • Set up verification keys — Enable cross-signing in your client for maximum security
  • Create a backup — See the Backup & Restore guide for full instructions
  • Set up SSH keys — If you haven't already, see Backup & Restore After Install
  • Explore the architecture — Learn what's running under the hood on the Architecture page
